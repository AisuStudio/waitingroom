waitingroom

A holding room for behaviour rules. Not production code — the place where a rule becomes executable before it gets built.

Components Flow

The flow

How a requirement becomes a component that can be built without asking back. Everything below is marked: what runs today, and what does not exist yet.

  1. 1

    Specification

    exists — their system

    States what must be possible — not how it looks. A spec that prescribes the control is reaching into design.

    So the behaviour is undefined here, and that is correct. It only becomes a problem if nothing further down defines it either.

  2. 2

    Design in Figma

    exists — their system

    States what it looks like. Components from the library, colour from the tokens.

    The behaviour goes into the component description: a few sentences, at the component, readable through the API.

    Figma holds states, not rules. Two variants show both sides of a threshold — they cannot say where it sits.

  3. 3

    Prose becomes a rule

    today by hand · skill planned

    Description, spec and the cross-cutting rules become one file: what applies, why, the edge cases, who decided — plus the executable logic.

    And a list of what none of them answered. Those are asked, never invented. An answer nobody chose is worse than an open question, because it looks like a decision.

    The skill standardises the questions, not the answers. Every threshold gets asked what happens at exactly N; every space conflict, what may not be sacrificed.

  4. 4

    waitingroom

    built — this is it

    The rule becomes executable. A control panel drives it past its own thresholds — what is on screen is the rule working, not one result somebody picked.

    Prototype, rule text and snippet come from one file. Change the threshold and all three follow.

    Explicitly not production code. That was the failure last time: something arrived looking like a delivery and was judged as one.

  5. 5

    Engineering checks it

    next step

    “Could you build this from it, without asking the designer?”

    Every “no, I'd still need…” is a line missing from the rule. That is the measurement; the prototype is only the means.

  6. 6

    Answers flow back

    built

    Answers become edge cases. Changes become entries in the change trail, with a reason — not silent edits that pretend it was always so.

    Two of the three rules already carry a second entry. Both were found by working the prototype, not by reading it.

  7. 7

    Implementation

    their system

    Built in the real stack, from a rule with no gaps left. The snippet is framework-neutral on purpose: the decision, not the rendering.

Which artefact carries what

Each exists so something does not have to be decided twice. That, not typing speed, is where throughput comes from.

ArtefactCarriesStatus
rules/*.js
one file per rule
 The single source. Prototype, rule text and snippet all derive from it. built
Figma component description
at the component
 The designer's intent, without a change of tool. in use
design.md
one level above the rules
 What holds everywhere, so it is not repeated per component: names, selection controls, missing data. Plus the rule types and their questions. planned
rules skill
prose → rule
 Same questions, same format, every time. Translates — never authors. planned
check script
runs on every change
 All fields present, change trail and open questions non-empty, and no parameter spelled out as a literal in prose — the drift that already happened here once. planned
docs/*.md
generated
 The linkable, archivable form of a rule. Output, never source. built

In that order: the check script first, because it makes consistency measurable; design.md from what the script cannot check; the skill last, because it needs both as its yardstick.

Where the throughput comes from

  • Fewer questions back. Every edge case settled in advance is a message not sent and a wait not had.
  • Fewer full rounds. A colour change is a token change. Where component and design point at the same token, nothing is rebuilt and nothing is handed over.
  • Fewer decisions. Once “from five options on, a select” is settled, component forty inherits it. This is the one that compounds — and why a design.md of decisions beats one of style guidance.

None of this makes anyone build faster. It removes the waiting in between.
