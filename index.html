waitingroom

A holding room for behaviour rules. Not production code — the place where a rule becomes executable before it gets built.

Where the rules sit in Figma

The designer states the behaviour in the component's own description — a few sentences, at the component, without leaving the tool they are already in. It travels with the component and is readable through the API, which is what makes it a channel rather than a note.

Component description, read back from Figma

BEHAVIOUR
Up to 4 options: radio group — every option visible at once.
From 5 options on: select — the list would otherwise crowd out the context.
Exactly one option: shown as a set value, not as a choice.
No options: the field is not rendered.

Spec: WR-104
Rule: waitingroom → Purpose selection → Rules

What it deliberately is not: a full specification. Where the threshold sits, what happens while options are still loading, whether one is preselected — those get settled here, where they can be executed and checked. Figma states the intent; this page states what happens in every case.

Each component's three views come from a single file in rules/. Change a threshold or a condition there and the prototype, the rule text and the code change together. There is no second place to keep in sync. All sample data is synthetic — an invented citizen registration office, with no connection to any real case or person.
